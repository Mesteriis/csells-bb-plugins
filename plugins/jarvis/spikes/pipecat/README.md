# Pipecat round-trip spike

Disposable research candidate only; **short-control acceptance failed**. Question: can a persistent WebRTC call carry real Jarvis input/output and spoken interruption while capture stays live?

The authenticated BB routes `/pipecat`, `/pipecat-ice`, and `/pipecat-offer` serve the page and proxy loopback4844. `server.py` uses Pipecat SmallWebRTC, Silero VAD, and output queues. It adapts the existing restricted relay on4842 for real STT/Jarvis/Alfred and Smart Turn on4843. No new model credentials or raw-audio persistence. Recognition and output use separate tasks. Long captions are synthesized in bounded segments without truncation; streaming requests have connect/read timeouts but no total playback-duration timeout. Logs record candidate/rejection/committed interruption separately and generated PCM bytes/duration, without transcript text. Start does not take over another audio owner.

Runtime: Python3.13; Pipecat source pinned at `1bc2e37b15566cd34bb6941a335ce09c3bbbab8c` with `[webrtc]`, plus aiohttp and fastapi. Install in an isolated venv, then run `python server.py`. Existing relay and turn services are required. Deployment and resolved dependencies are preserved in the task staging evidence directory; this is not a standalone production installer.

TURN credentials are HMAC-issued for five minutes from the candidate-only `/home/tester/jarvis/turn-secret`. Set `JARVIS_TURN_URL` to the reachable TCP TURN URL. Default is the private test tunnel `turn:127.0.0.1:4845?transport=tcp`; it does not work on a user's remote phone. Coturn restricts peer destinations to the candidate VM, quotas to four allocations and relay ports49160–49163. Only TCP3478 needs public forwarding because both the TURN relay and Pipecat peer terminate in this VM. Chris approved temporary TCP3478 forwarding on2026-11-14; it is installed through Dragon to the candidate until2026-11-18T23:59:59Z. The running candidate overrides JARVIS_TURN_URL with the verified public address; the source default remains a private development tunnel.

The UI has Start, What's going on, Stop speaking, and End. Microphone speech goes through the same real director as the main plugin. In AEC mode, cleaned speech onset or explicit Stop cancels the active output task, broadcasts Pipecat interruption to clear pending output, and cancels the director generation. Capture remains active. Output pacing bounds application queue growth. The probe keeps the audio track alive; it does not close it on each interruption.

With `JARVIS_AEC3=1`, browser WebRTC AEC remains enabled. An additional AEC3 stage receives synchronized microphone/reference channels over stereo Opus, cleans the microphone before Silero and allows immediate onset interruption independently of batch STT. The reference is a tap of the received track, not a physical loudspeaker measurement. The preserved variant uses server NS; disabling it improved some speech but reintroduced false echo interruptions. Neither variant is accepted. See [AEC-BUILD.md](AEC-BUILD.md) for the pinned native dependency, patch and build instructions. Per-second logs expose input/output/reference RMS and diagnostic lag/coherence; capture settings are recorded without raw microphone audio. The page retains native remote-track playback and never continuously mutes capture during output.

Limits: this paired-reference integration is experimental. Physical Android/car qualification,250ms interruption acceptance, semantic backchannel handling, reversible false-interruption resume, word-accurate heard-text history, streaming STT and unsolicited watched updates remain open. Generated completion is not physical playback or approval delivery. Reconnect requires End/Start. Without the AEC flag, legacy transcript matching remains the slower fallback; it is not the selected acoustic architecture. Do not promote this prototype as the completed conversation implementation.
