# Voice and concurrent-work source review for BB Jarvis

Reviewed 2026-11-14. This is a code-reading study, not a new live benchmark or security certification. No reviewed project was installed or executed. Current default branches were shallow-cloned and pinned below. The existing awesome-jarvis lab report is historical execution evidence and must not be conflated with current-source findings.

## Recommendation

Use Qwen Audio Agent as the main reference for the conversation/task boundary and durable announcement delivery, Paseo for the streaming-STT/PCM/provider contract and explicit playback acknowledgements, and Pipecat for the semantic turn-detection dependency evaluation. Keep BB as the worker runtime. Do not import another assistant's agent daemon or permission defaults merely to obtain its voice UI.

There are concrete reusable modules, not just architectural inspiration: Qwen's small turn-state/correlation classes and notification-claim queue are the best first extraction candidates. Port these with their tests and provenance into the plugin's own domain layer, then adapt persistence and thread operations to BB. Evaluate Pipecat Smart Turn as an actual pinned dependency or narrow inference sidecar before building a semantic detector ourselves. These are engineering recommendations from source inspection, pending BB/Pocket integration and real-microphone measurements.

## Qwen Audio Agent: strongest transferable control boundaries

**Observed input lifecycle.** `RealtimeInputRuntime` translates provider speech/transcription events and typed submissions into a shared turn model. Speech onset clears the response candidate, dismisses an active announcement, emits playback-clear and cancels the frontend response. Task execution is outside this module. Invalid, duplicate and stale transcripts are discarded; typed input supersedes an active voice turn. This separation maps well to our distinction between barge-in and explicit stop-work. Source: [server/src/voice/realtime-input-runtime.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/voice/realtime-input-runtime.mjs).

**Observed generation mechanism.** `RealtimeTurnState` owns monotonically advancing turn generations; manual submission invalidates older input correlations, and closing advances the boundary before clearing correlations. Staleness is measured against the committed turn generation. Adopt the small state/correlation pair as an extraction candidate rather than reimplementing ad hoc booleans across microphone, network and playback handlers. Preserve its distinction between current and committed generations and extend tests for BB dispatch: invalidating speech cannot undo an already accepted worker action. Sources: [server/src/voice/realtime-turn-state.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/voice/realtime-turn-state.mjs), [server/src/voice/turn-correlation.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/voice/turn-correlation.mjs).

**Observed task/presentation split.** `SessionTaskCoordinator` observes task-domain events; closing it unsubscribes and releases presentation state without cancelling accepted work. Pending permissions and ordinary structured input have separate maps. It refreshes the exposed response tools before presenting a request. Each attempt has an identity so completion of an old promise cannot clear a newer retry. Delivery requires ready/output-enabled/not-sleeping state and waits during a busy conversational turn. This directly informs microphone-off announcements and reconnect behavior. Source: [server/src/orchestration/session-task-coordinator.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/orchestration/session-task-coordinator.mjs).

**Observed durable delivery model.** `TaskNotificationQueue` claims pending notifications for one claimant, filters owner/session, renews/releases leases and reclaims expiry. It checkpoints delivery before notifying observers. Thus a browser disconnection need not lose a result or reexecute work. Adopt the claim/acknowledgement state machine, with BB storage transactions replacing the mutable-record persistence hook. Do not mark speech delivered at TTS first byte: acknowledge actual playback or deliberate visual dismissal. Source: [server/src/task/task-notification-queue.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/task/task-notification-queue.mjs).

**Observed receipts.** `AgentTaskRuntime` returns acceptance/duplicate receipts and keeps bounded update receipts across frontend replacement via the task manager's lifetime. A repeated answer remains a receipt instead of falling through into task steering. These in-memory receipts are not by themselves crash-durable; our plan still needs persisted dispatch intent and reconciliation after uncertain BB API responses. Source: [server/src/frontend/tools/agent-task-runtime.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/frontend/tools/agent-task-runtime.mjs).

**Observed permissions, with a boundary not to copy.** The ACP broker generates unpredictable request IDs, resolves opaque provider option IDs by supported kind, checks the owner on response, caches bounded idempotent results and cancels requests by scope. But `full` mode and identified internal session tools bypass ordinary prompting. Reuse correlation and schema validation; retain BB/user policy rather than adopting these bypass rules. The broker alone does not prove correct interpretation of spoken consent. Source: [server/src/backend/adapters/acp/permission-broker.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/backend/adapters/acp/permission-broker.mjs).

**Observed cancellation.** The backend adapter aborts the owning work before cancelling children, preventing the aggregate waiter from producing a fresh summary during cancellation. It waits for work settlement, retains the session lease through cleanup and has a bounded cancellation timeout with an unconfirmed outcome. Lower-level `cancelSession` sends an ACP notification, which alone proves neither termination nor side-effect rollback. Our BB adapter must retain the stronger process-termination acceptance test. Sources: [server/src/backend/adapters/acp/backend-adapter.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/backend/adapters/acp/backend-adapter.mjs), [server/src/backend/adapters/acp/process-client.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/src/backend/adapters/acp/process-client.mjs).

**Tests worth porting as scenarios.** Existing coordinator tests cover stale request promises, reconnect redelivery without task reexecution, output-disabled result claiming, owner/session isolation, cancelled-task progress suppression and clients unable to confirm notification delivery. A test explicitly rejects synthesizing structured permission/input requests from ordinary backend prose. Our additional “possible ordinary question” UX must preserve that distinction: conversational text can be highlighted without becoming an approval object. These tests were inspected, not run. Sources: [server/test/session-task-coordinator.test.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/test/session-task-coordinator.test.mjs), [server/test/permission-broker.test.mjs](https://github.com/QwenAudio/qwen-audio-agent/blob/02990dc159d2a6d211f4563daa5120ac9979a0bf/server/test/permission-broker.test.mjs).

## Paseo: useful streaming boundaries, thresholds need care

**Observed streaming pipeline.** `createVoiceTurnController` independently resamples input for its detector and STT provider, sends audio continuously to both, commits STT on speech stop, gathers committed segment IDs and assembles final text in commit order. It suppresses duplicate/stale partials, excludes filler-only partials, bounds final-transcript waiting to ten seconds, and permits one STT reconnect attempt per turn. A finalization timeout can return the finals received so far; our command path should explicitly mark incomplete recognition rather than accept a truncated approval. Source: [packages/server/src/server/session/voice/voice-turn-controller.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/session/voice/voice-turn-controller.ts).

**Observed detector is acoustic, not semantic completion.** The inspected local Sherpa/Silero path uses 16 kHz audio, 512-sample windows, 800 ms confirmation and 1000 ms silence defaults. It is a useful four-state debounce machine, but that default silence alone exceeds our approximate 800 ms end-of-speech-to-useful-audio target. Do not copy thresholds or label this detector semantic. Benchmark short “yes/no” turns as well as false starts. Source: [packages/server/src/server/speech/providers/local/sherpa/silero-vad-session.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/speech/providers/local/sherpa/silero-vad-session.ts).

**Observed interruption and played acknowledgements.** The current session handler interrupts on confirmed VAD rather than awaiting the transcript, aborts synthesis/playback and asks its host to interrupt the voice agent. It reports interruption failure visibly. `handleAudioPlayed` passes a client acknowledgement to TTS tracking. This is a good delivery boundary, but voice-agent interruption is not evidence that every delegated subprocess stopped. Sources: [packages/server/src/server/session/voice/voice-session.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/session/voice/voice-session.ts), [packages/server/src/server/agent/tts-manager.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/agent/tts-manager.ts).

**Observed PCM helper.** `Pcm16MonoResampler` preserves fractional position and a carry sample across chunks and rejects odd byte lengths. It is a compact TypeScript extraction candidate for reference/tests, but uses linear interpolation; that is not evidence of high-quality downsampling or adequate anti-aliasing. Pocket's 24 kHz PCM should be scheduled at its correct rate or passed through a verified resampler, never relabeled. Source: [packages/server/src/server/agent/pcm16-resampler.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/agent/pcm16-resampler.ts).

**Observed permission policy.** The current voice auto-allow helper permits only normalized speech-tool requests, rejecting non-tool and other requests. This is narrower than “voice may approve everything.” Current source does not erase historical behavior. The local awesome-jarvis October report records successful voice/barge-in and a real child result, but also spoken-approval failure and a Codex subprocess surviving stop. Preserve that adverse test as a regression to beat with actual execution. Sources: [packages/server/src/server/voice-permission-policy.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/voice-permission-policy.ts), [awesome-jarvis execution report](/Users/csells/code/csells/awesome-jarvis/lab/evidence/2026-10-06-retest/README.md).

**Tests worth porting as scenarios.** The turn-controller suite explicitly checks silence-only input, filler partials, once-only partial notification, committed segment ordering, stale finals and finalization timeouts. Import scenarios against the chosen BB/STT adapter rather than copying test doubles and calling them lab acceptance. Source: [packages/server/src/server/session/voice/voice-turn-controller.test.ts](https://github.com/getpaseo/paseo/blob/cec92d0be66b256794810a27efee1007eb7bf0ed/packages/server/src/server/session/voice/voice-turn-controller.test.ts).

## Established turn-taking frameworks

**Pipecat observed.** Current strategy configuration separates turn start from stop, supports first/all composition, and clears stop decisions when speech resumes. Defaults combine VAD/transcription start with Smart Turn end detection. `TurnAnalyzerUserTurnStopStrategy` combines audio/VAD/model completion with finalized transcription; otherwise it uses measured STT latency metadata to bound transcript waiting. This is the right model for “silence is not conversational completion.” Sources: [src/pipecat/turns/user_turn_strategies.py](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/turns/user_turn_strategies.py), [src/pipecat/turns/user_stop/turn_analyzer_user_turn_stop_strategy.py](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/turns/user_stop/turn_analyzer_user_turn_stop_strategy.py).

The local Smart Turn implementation is an actual ONNX dependency path, not merely a pattern: it uses NumPy, ONNX Runtime, a resampler, 16 kHz model input and a bundled smart-turn-v3.2 CPU model. Start by measuring this existing implementation through a narrow sidecar in the disposable VM; compare against a supported provider detector. Porting its feature extraction to browser JavaScript is extra engineering and must match preprocessing/model outputs before replacing the original. Audio diagnostic logging is opt-in; keep it off by default. Model artifact provenance/terms require separate review before distribution. Source: [src/pipecat/audio/turn/smart_turn/local_smart_turn_v3.py](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/audio/turn/smart_turn/local_smart_turn_v3.py).

**LiveKit observed.** Agent activity treats false interruption recovery as a distinct state. Resumption requires enabled policy, a timeout, an audio output able to pause, and matching non-interrupted speech-handle state; it reconciles stale pause references. This is useful for conversational backchannels and coughs, but our explicit stop must remain terminal. Borrow the state distinction first, not the entire room/agent infrastructure. Source: [livekit-agents/livekit/agents/voice/agent_activity.py](https://github.com/livekit/agents/blob/cbb5770c716c70009969cd7fa88e3c3662222ce9/livekit-agents/livekit/agents/voice/agent_activity.py).

## Bootstrap sequence and unresolved proofs

1. Start with source-attributed Qwen turn/correlation and notification-claim primitives, translated to typed BB domain records. Port race scenarios first: late chunks, duplicate answers, reconnect, competing clients and expired claims.
2. Bind worker operations to BB and the approved restricted staging relay. Preserve Qwen's accepted-work/connection separation, but require BB-enforced ownership, current interactions and durable dispatch reconciliation.
3. Implement the speech adapter using Paseo's separated detector/STT contracts and ordered finalization. Integrate existing Pocket Alfred transport; do not bring Paseo's provider runtime or default VAD timings wholesale.
4. Compare Pipecat Smart Turn against available supported detector alternatives on Chris's actual mic/browser and the specified 30-turn suite. Select only after measuring clipped turns, false interrupts, finalization loss and end-to-audio latency. Neither this review nor upstream unit tests establishes those numbers.
5. Verify played acknowledgements, explicit stop versus barge-in, and actual owned process termination in the real lab. Benchmark the historical Paseo failure explicitly; newer source is not a retest.

Still unverified: runtime quality/current regression status of all four projects, multilingual behavior, actual BB talker latency, browser-side detector packaging, exact model redistribution terms, and whether extracting the candidate primitives is less maintenance than consuming a published upstream module. The source choices narrow implementation work; they do not waive staging or acceptance gates.
