# Four browser duplex framework implementations: source audit

2026-11-14. Code inspected, not run on Android hardware. Four distinct stacks are covered; a framework and its browser SDK count as one, not two implementations. Clones are under `/tmp/jarvis-mobile-audit/`; earlier browser SDK clones remain under `/tmp/jarvis-duplex-research/`.

## Pipecat: concrete reuse proposal

The browser [SmallWebRTC transport](https://github.com/pipecat-ai/pipecat-client-web-transports/blob/09956702aea9d01ee46cebbfcc9911d913e360b9/transports/small-webrtc-transport/src/smallWebRTCTransport.ts) sends a microphone track and receives a remote audio track. Its connection-failure logic retries after persistent disconnect, recreates the peer connection rather than assuming aiortc ICE restart works, and bounds attempts (around lines 560–610). The example attaches remote audio to `audio.srcObject`. Its DailyMediaManager disables the local WAV recorder/player, so adopting it does not preserve our custom WAV playout architecture. See the [earlier direct transport audit](android-duplex-webrtc.md) for source links and device lifecycle details.

Server output [AudioTrack, lines 103–195](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/transports/smallwebrtc/transport.py#L103) paces 10 ms PCM frames, advances timestamps continuously and produces idle silence. `write_audio_frame` awaits the outgoing chunk's consumption (line 502), creating backpressure. That future means the server track consumed samples, not that car speakers played them.

**Cancellation is layered, not one magic flush call.** [FrameProcessor `_start_interruption`, line 1161](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/processors/frame_processor.py#L1161) cancels and recreates processing tasks and drops interruptible queued frames. [TTS interruption, line 1539](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/services/tts_service.py#L1539) resets aggregation and removes interruptible synthesis contexts, invokes `on_audio_context_interrupted(context_id=...)`, and resets word timing. Alfred's adapter must implement cancellation of its outstanding HTTP synthesis and reject late chunks by context identity. [LLM service line 1100](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/services/llm_service.py#L1100) separately cancels functions marked `cancel_on_interruption`; this must not cancel BB delegated work merely because the user speaks over the briefing.

[Base output interruption, line 609](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/transports/base_output.py#L609) drains interruptible audio/clock queues and partial buffered audio, retaining explicit uninterruptible content. It intentionally keeps the current audio write alive. **The SmallWebRTC track itself exposes `stop()`, not an ordinary barge-in flush method; stop clears its queue and ends the track.** Do not call track.stop for every interruption. Default output chunking is four 10 ms chunks ([transport parameters line 117](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/transports/base_transport.py#L117)); the active chunk and network/browser buffers can still drain after cancellation. Measure this tail. It is not a promise of instantaneous acoustic silence.

[Turn strategies, lines 405–427](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/turns/user_turn_strategies.py#L405) combine VAD/transcription start with Smart Turn stop. This separates prompt interruption from deciding the user has finished. [Assistant aggregation, line 2223](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/src/pipecat/processors/aggregators/llm_response_universal.py#L2223) closes the assistant turn as interrupted and resets aggregation. This is not hardware playback acknowledgement; align only delivered text/timestamps where available and do not record an entire generated but cancelled response as heard.

**Proposed integration:** browser Pipecat client + SmallWebRTC transport → real VM SmallWebRTC input → server VAD/Smart Turn and existing real STT adapter → BB coordinator/model adapter → Alfred TTS service adapter → SmallWebRTC output → persistent native remote-track element. This removes the browser's forced16k worklet, local turn buffers and sentence WAV queue from the media path; perform model-specific resampling server-side. Retain the BB relay authority boundaries unchanged. Keep captions and questions on an authenticated control path; media interruption is distinct from explicit delegated-work cancellation.

Minimum dependency footprint is Pipecat plus its `webrtc` extra (aiortc and OpenCV listed in [pyproject](https://github.com/pipecat-ai/pipecat/blob/1bc2e37b15566cd34bb6941a335ce09c3bbbab8c/pyproject.toml#L169)), model runtime already used by the turn sidecar, browser client/transport and their transitive device-management dependencies. Inspect locked resolved packages rather than claiming the extra is tiny. Reuse the BSD-2-Clause implementation with notices. A real cellular session also needs reachable ICE candidates and authenticated, short-lived TURN credentials where direct connectivity fails. The existing HTTPS Connect exposure does not relay RTP.

**Acceptance hooks:** record turn/context IDs, speech onset, InterruptionFrame transit, Alfred request cancellation, output queue tail, first decoded RTP, RTP loss/jitter, capture energy, connection recovery and old-context drops. Drive actual STT/Alfred through the VM, then interrupt during generation, queued audio and active playback; verify no old answer resumes after a real interruption, capture continues, and only explicit stop-work cancels BB work. Test silent pauses, short yes/no, cough/backchannel, Wi-Fi/cellular switch, Bluetooth disconnect and page resume. No source audit establishes the car's acoustic result.

## LiveKit: stronger playback accounting

JS [capture defaults](https://github.com/livekit/client-sdk-js/blob/15ca1f39f0eded2b4ce2f525a7dcbcf6e7e3b9c7/src/room/defaults.ts#L18) request AEC, noise suppression and gain control; webAudioMix defaults false. Native remote-track attachment avoids putting output into a custom Web Audio graph. The agent [partial-output handling](https://github.com/livekit/agents/blob/cbb5770c716c70009969cd7fa88e3c3662222ce9/livekit-agents/livekit/agents/voice/agent_activity.py#L4888) truncates supported realtime-model messages at the recorded playback position and forwarded transcript. Its [false interruption state](https://github.com/livekit/agents/blob/cbb5770c716c70009969cd7fa88e3c3662222ce9/livekit-agents/livekit/agents/voice/agent_activity.py#L5182) requires a pausable output, matching speech handle and enabled policy. Timeout waits for unresolved end-of-turn decisions rather than resuming a response during a still-pending user turn. Useful policies to retain even if Pipecat supplies media.

This requires room/SFU/token infrastructure plus Agents, rather than just swapping a media element. Code is Apache-2.0; covered turn models have a separate MODEL_LICENSE. [Upstream Android issue1507](https://github.com/livekit/client-sdk-js/issues/1507) reports Bluetooth routing failures in mobile Chrome and playgrounds, with some devices succeeding and others switching output; it is closed as not planned. This is adverse upstream user evidence, not a controlled finding about Chris's car, and prevents claiming a universal WebRTC cure.

## TEN: separate cancellation at every audio stage

The [playground RTC manager](https://github.com/TEN-framework/ten-framework/blob/619abefc1bb0865be681aa531a4d5dfe2bece868/ai_agents/playground/src/manager/rtc/rtc.ts#L70) uses `AgoraRTC.createMicrophoneAudioTrack()` with SDK defaults, publishes it, subscribes to remote audio (line151) and calls its `play()` (line309). AEC and routing internals are delegated to Agora; the wrapper alone does not establish realized constraints or Bluetooth correctness.

The [TEN VAD example](https://github.com/TEN-framework/ten-framework/blob/619abefc1bb0865be681aa531a4d5dfe2bece868/ai_agents/agents/examples/voice-assistant-with-ten-vad/tenapp/ten_packages/extension/main_python/extension.py#L113) calls interruption on speech-start. [Its interruption method line204](https://github.com/TEN-framework/ten-framework/blob/619abefc1bb0865be681aa531a4d5dfe2bece868/ai_agents/agents/examples/voice-assistant-with-ten-vad/tenapp/ten_packages/extension/main_python/extension.py#L204) clears sentence fragments, awaits LLM flush, sends a UUID-tagged TTS flush and sends RTC flush. The accompanying `agent/agent.py:194` cancels in-flight dispatch and drains queued LLM events. This is a valuable multi-stage cancellation contract, but sending flush commands does not prove the remote device already stopped or a delegated side effect rolled back.

Adoption adds Agora credentials/network dependency and TEN runtime/extensions. The [root license](https://github.com/TEN-framework/ten-framework/blob/619abefc1bb0865be681aa531a4d5dfe2bece868/LICENSE) adds deployment and competition restrictions to Apache language. Treat it as constrained reuse, not plain Apache. No mobile car acceptance or reliable false-interruption resume was verified in this example.

## FastRTC: duplex transport, slower default interruption decision

[Browser track attachment](https://github.com/gradio-app/fastrtc/blob/59ca4f77e1669a9599c0895fd0d7c39f356bf89f/frontend/shared/webrtc_utils.ts#L28) installs the remote stream as `srcObject`; line95 adds local tracks; line134 exchanges trickle ICE. `InteractiveAudio.svelte:114` calls getUserMedia with supplied `track_constraints`; this read does not establish a special Android AEC fix. Playback rejection is only logged in this helper, so Jarvis must not inherit that invisible failure UX.

The important distinction is in [ReplyOnPause.receive, lines289–297](https://github.com/gradio-app/fastrtc/blob/59ca4f77e1669a9599c0895fd0d7c39f356bf89f/backend/fastrtc/reply_on_pause.py#L289): active capture is processed during response, but generator closure and output queue clearing occur when **pause_detected** becomes true. `started_talking` is logged earlier without that cancellation. `_close_generator` times out async closure after one second and logs failure at debug level. [Track queue clear line742](https://github.com/gradio-app/fastrtc/blob/59ca4f77e1669a9599c0895fd0d7c39f356bf89f/backend/fastrtc/tracks.py#L742) drains pending output and resets pacing origin. It does not retract already-delivered RTP.

Therefore `can_interrupt=True` is not equivalent to immediate barge-in. MIT licensed and compact for transport experiments, but a custom StreamHandler policy would be needed for Jarvis's speech-start interruption, cancellation visibility and delivered-context accounting. No Android Bluetooth or reconnect acceptance was run here.
