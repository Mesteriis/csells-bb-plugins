# Hermes and Happy: source review for BB Jarvis

Reviewed 2026-11-14, before implementation. This is a source inspection, not a fresh runtime qualification. Shallow clones of the current default branches were fetched into temporary directories; no dependencies were installed or applications run. Hermes HEAD: `1c5deb2f70cc262dfc3ab5f57107165dbe271c97`; Happy HEAD: `83eab87c435a85e8bec7fa9c81db3dbbea700db2`.

## Selection and evidence quality

These projects earn close inspection for complementary reasons: Hermes combines conversation, delegation, curated memory and a desktop staff view; Happy concentrates on supervising existing coding sessions from another client. Chris's local awesome-jarvis [test report](https://github.com/csells/awesome-jarvis/blob/0378a6801dda9a3345ea7d4a53614f3cd410763f/testing.md) records successful Hermes desktop barge-in and delegated-worker interruption, but failed CLI barge-in and a smart approval of a destructive test-folder command. Happy's recorded test exercised two sessions, edit/command approval and inference cancellation from a phone, but voice was blocked by the emulator microphone. Those older results establish selection rationale, not current-runtime proof.

The current Happy checkout differs materially from its architecture document: `docs/voice-architecture.md` references React Native `happy-app` paths absent from this checkout. Its native Android implementation now provides inspectable equivalents. Claims below use actual Android/CLI code; the old document alone is insufficient evidence. [Historical architecture document](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/docs/voice-architecture.md).

## Hermes: separate durable knowledge from conversational recall

**Observed.** The built-in memory tool owns bounded `MEMORY.md` and `USER.md` stores. `MemoryStore` serializes updates under a file lock, reloads disk state for mutations, checks content, applies atomic batches against the final character budget and writes atomically. It refuses unreadable/external-drift states rather than overwriting them as empty. Replace/remove approval pins the entire matched entry so a later changed entry cannot inherit approval merely by matching the same substring. These are useful concurrency and correction invariants. [Store](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/memory_tool_store.py), [mutation and approval layer](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/memory_tool.py#L63).

**Observed limitation.** The prompt snapshot is frozen at session start for cache stability; `format_for_system_prompt` returns that snapshot rather than current disk state. Entries are strings separated by a delimiter, not first-class fact records with source-event IDs, confidence, revisions and deletion suppression. The inspected store also creates drift backups. Thus its built-in remove operation is not evidence of BB's required deletion across all derived caches, snapshots and backups. [Frozen snapshot and persistence](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/memory_tool_store.py#L655).

**Decision for BB.** Adopt bounded curated memory and atomic compare-before-change semantics, but retain the planned structured records and source links. Use a stable small preference prefix plus versioned relevant retrieval; immediately invalidate corrected/deleted derived retrieval instead of copying Hermes's session-frozen stale-memory behavior. Preserve truthful distinctions between original history, derived memories and retained backups.

**Observed.** `session_search_tool.py` supplies a distinct history-recall path. It resolves parent/compaction lineage, distinguishes compression summaries, deduplicates discoveries by lineage, supports time/role filters and bounded result counts, and exposes session metadata. This is a much better bootstrap for “Why did we decide that?” than adding every transcript to personal memory. [Search and lineage implementation](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/session_search_tool.py#L107), [discovery](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/session_search_tool.py#L358).

**Decision for BB.** Implement two-stage recall using BB's existing search/history APIs: find relevant thread/message references, then retrieve bounded source context. Link the actual decision and separately report later corrections. BB already owns transcripts; do not import Hermes's transcript database or summary format.

## Hermes: background staff and interruption are different lifecycles

**Observed.** Background delegation returns task/delegation handles, tracks child IDs, records completed children durably, and can split grouped tasks into independent completion units. The parent gets a result later, rather than synchronously waiting in the talker loop. `independent_completions` is deliberately off by default because one completion turn per worker can fragment orchestration. Detached units ignore the parent's turn interrupt while their own stop callback signals their children. [Dispatch implementation](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/delegate_tool_dispatch.py#L118), [handles and completion grouping](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/delegate_tool_dispatch.py#L380).

**Observed limitation.** When background execution is unsupported or pool capacity is exhausted, this implementation includes synchronous fallback paths. That is unsuitable for our fast talker: BB Jarvis should queue or return a visible capacity error, never silently become synchronous. The parallel foreground path can report interrupted and abandon a still-pending future after signaling; this is not proof every child OS process terminated. [Fallback and parallel execution](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/delegate_tool_dispatch.py#L150).

**Observed regression lesson.** A dedicated test documents a previous bug in which a background completion was treated as ordinary user input and interrupted a busy parent. It asserts internal events queue silently until idle. [Regression test](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tests/gateway/test_internal_event_never_interrupts_busy_session.py).

**Decision for BB.** Reuse the separation of user input from internal completion events, bounded completion batches, immediate task handles and independent speech/work lifecycles. Let BB retain scheduling and process ownership. Translate the regression into a contract test: task A completes while Chris speaks to Jarvis about B; the completion cannot abort B, and its later announcement occurs exactly once.

## Hermes: useful speech lifecycle code, unsafe defaults to avoid importing

**Observed.** The desktop chained-voice hook captures the STT owner once per conversation, holds a conversation identity across awaits, invalidates obsolete responses, separates recorder/playback state, warms STT, detects TTS echo and parks a captured utterance if it cannot submit after interruption. This is valuable concrete recovery behavior: a late transcription must never submit after stop/restart, and user speech must not silently vanish when busy state fails to settle. [Voice hook](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/apps/desktop/src/app/chat/composer/hooks/use-voice-conversation.ts#L29), [boundary test](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/apps/desktop/src/app/chat/composer/hooks/use-voice-conversation-boundary.test.tsx).

**Decision for BB.** Port lifecycle invariants and regression cases into a small generation-based controller; keep Pocket's owner/lease separate from browser microphone ownership. The Hermes hook imports app stores, owner/profile APIs and UI callbacks, so direct vendoring would drag in the desktop architecture. Its `onInterrupt` stops an agent turn; BB's barge-in should stop the talker's reply while delegated workers continue unless explicitly targeted.

**Observed.** `approval_smart.py` uses an auxiliary model to classify commands; this is a risk judgment, not the user's approval. `approval_provenance.py` separately explains previously authorized silent approvals and explicitly says provenance does not itself decide authorization. The memory tool's `_gate_or_stage` returns permission to proceed if its gate module fails to load. [Smart approval](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/approval_smart.py), [authority provenance](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/approval_provenance.py), [memory gate failure](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/tools/memory_tool.py#L83).

**Decision for BB.** Adopt authority provenance in audit records and avoid repetitive approval for authorized work. Do not adopt a model verdict as user consent, or fail-open gate imports. Keep policy enforcement in BB/provider/tool paths and disclose prompt-only limitations.

**Observed persona approach.** Hermes uses a separate `SOUL.md` identity/personality input with trust distinctions for user-authored versus distributed profiles; prompt refresh handles changes to long-lived sessions. [Prompt builder](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/agent/prompt_builder.py#L85), [refresh](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/agent/prompt_refresh.py). BB can use a small editable persona configuration and explicit revision refresh without importing a full personality file system. Persona never grants tool authority.

## Happy: explicit target routing and stale-call protection

**Observed.** Native Android `VoiceTools` exposes explicit-session messaging and permission decisions. Permission routing looks up the owning session from the request ID; it rechecks whether the voice session remains current after that suspendable lookup. Its tests cover a call ending during lookup, invalid arguments, wrong/missing request IDs and failure without a success counter. [Tools](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-android/app/src/main/kotlin/com/slopus/happy/voice/VoiceTools.kt), [tests](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-android/app/src/test/kotlin/com/slopus/happy/voice/VoiceToolsTest.kt).

**Observed.** `VoiceEngine` increments a generation before teardown and gates callbacks against it. `VoiceHooks` distinguishes silent context updates from response-triggering prompts, batching the latter until idle. `StoreVoiceContext` observes messages and permission-state changes and hydrates target context. [Engine](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-android/app/src/main/kotlin/com/slopus/happy/voice/VoiceEngine.kt#L56), [hooks](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-android/app/src/main/kotlin/com/slopus/happy/voice/VoiceHooks.kt#L42), [store observation](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-android/app/src/main/kotlin/com/slopus/happy/voice/StoreVoiceContext.kt).

**Decision for BB.** Bootstrap the coordinator around explicit thread + interaction + presentation-generation identifiers, with revalidation after asynchronous reads. Adopt separate context and announcement channels. Extend the pending queue with durable dedupe, expiry, supersession and quiet mode; Happy's inspected in-memory string queue is not that durable contract. Never infer an approval target from whatever thread happens to be selected after a delay.

**Limitation.** Happy's voice tool schema does not itself prove Chris said yes to a particular currently visible action; the language model can invoke the tool. It is useful routing code, not a complete voice authorization boundary. It also does not supply Jarvis's sourced lifelong personal memory.

## Happy: cancel pending decisions before stopping work

**Observed.** The CLI `BasePermissionHandler` maps pending requests by ID, ignores already-resolved replies, moves resolved requests into completed state, and removes an old completed entry when a provider reuses the same tool-call ID for a new approval. `abortAll` resolves pending approvals as abort before cancellation, allowing blocked providers to process stop. [Permission handler](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-cli/src/utils/BasePermissionHandler.ts#L75).

**Observed.** Codex `handleAbort` coalesces concurrent aborts, calls `abortAll`, requests `abortTurnWithFallback` with a three-second grace period and forced backend restart on timeout, then reports whether the previous thread resumed. It distinguishes turn cancellation from terminating the session. Its catch logs an abort error rather than proving termination. [Codex abort flow](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/packages/happy-cli/src/codex/runCodex.ts#L414).

**Decision for BB.** Use that ordering as a test blueprint: cancel owned pending decisions/queued restarts, request stop, observe the real runtime and owned process outcome, report unconfirmed cancellation explicitly. Do not import Happy's provider processes or force-restart unrelated BB runtimes. Provider-specific fallback belongs in BB's provider adapter, with visible scope and real termination evidence.

## Reuse boundary, licenses, and concrete bootstrap order

Both pinned repositories carry MIT root licenses: [Hermes license](https://github.com/NousResearch/hermes-agent/blob/1c5deb2f70cc262dfc3ab5f57107165dbe271c97/LICENSE), [Happy license](https://github.com/slopus/happy/blob/83eab87c435a85e8bec7fa9c81db3dbbea700db2/LICENSE). They permit code adaptation subject to retaining applicable notices; separately check vendored modules, assets and dependencies before copying. This review copied no implementation source. It is not a blanket license audit.

| Bootstrap item | Reuse form | BB work still required |
| --- | --- | --- |
| Happy request-owner lookup, generation fencing, abort ordering | Adapt algorithms and contract-test cases | BB typed handlers, interaction fingerprint/currentness, authority, process verification |
| Hermes conversation identity and parked-utterance recovery | Adapt controller invariants and tests | Browser capture, Pocket streaming/leases, latency/turn-quality measurement |
| Hermes bounded memory mutations and history search separation | Adapt storage/retrieval design | Structured provenance, invalidation/deletion suppression, BB history adapters |
| Hermes async completion batching | Adopt event/control model | BB persisted cursor, task ownership, dispatch reconciliation and no synchronous fallback |
| Existing BB provider/session machinery | Reuse directly | Current SDK capability validation; no second agent runtime |

Start with coordinator and generation-race tests; then speech lifecycle; then structured memory and source recall. The sources above provide executable test ideas, but none replaces end-to-end verification in the actual VM candidate against real BB/Pocket. Fresh source inspection does not overturn the older lab's failed voice/cancellation evidence without new runtime testing.
