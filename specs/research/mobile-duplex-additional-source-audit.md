# Mobile duplex source audit: AIRI, N.E.K.O, OpenAI Agents JS

Date: 2026-11-14. Scope: source inspection, not execution or Android/car qualification. Repositories cloned under `/tmp/jarvis-mobile-audit`. The first two are actual companions in Chris's awesome-jarvis list; the third is a voice transport/reference SDK from its building-block section. These are three projects, not three proven Bluetooth implementations.

## AIRI

Pinned `moeru-ai/airi` at `91eb562e3edfc624d1150985cdc6ffe7617e8ab7`. [Root license: MIT](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/LICENSE).

**Media.** The browser microphone source uses a shared AudioContext keyed by context options; it resumes during initiation and acquires getUserMedia. Its worklet capture tap connects through a zero-gain node to the destination. This is a Web Audio pipeline, not a native received WebRTC audio track. It stops owned tracks on scope cleanup and distinguishes borrowed streams from owned microphones. Capture readiness is shared while loading the worklet, avoiding serial setup delay. [sources.ts:25–180](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/packages/audio/src/browser/sources.ts#L25).

**AEC and speech onset.** The default voice listening plugin uses Silero VAD and configurable silence/end judging. Crucially, its default `acceptSpeech` permits automatic barge-in during speech only when the captured stream reports echo cancellation, unless an external classifier is provided. The microphone options request processing, but the source reads realized settings. Do not copy a UI's “always listening” label without this policy. [voice.ts:575–635](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/packages/stage-ui/src/stores/voice.ts#L575), [audio-device.ts:106](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/packages/stage-ui/src/composables/audio/audio-device.ts#L106).

**Interruption.** VoiceController deduplicates targets by turn identity, separates the promise that audio is silenced from the promise that interruption is recorded, and retries failed recording by clearing only its pending notification. VoiceResponse stops the playback group, aborts its producer signal, and cancels every speech stream. Recording carries a playback receipt, not merely “generation ended.” The UI forwards this into chat interruption handling. [controller.ts:271–332](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/packages/core-agent/src/voice/controller.ts#L271), [response.ts:546–570](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/packages/core-agent/src/voice/output/response.ts#L546), [voice.ts:135](https://github.com/moeru-ai/airi/blob/91eb562e3edfc624d1150985cdc6ffe7617e8ab7/packages/stage-ui/src/stores/voice.ts#L135).

**Reuse decision.** Strong donor for interruption receipts, explicit ownership of live resources, and echo-aware policy. Adopting its Web Audio graph does not resolve our Android routing evidence; no phone/car qualification found in the inspected paths. Its graph includes the muted destination connection we are specifically investigating. Read controller tests as regression donors, not evidence of physical audio. No code copied in this audit.

## N.E.K.O

Pinned `Project-N-E-K-O/N.E.K.O` at `6cc6cff2caff1dcc6d8b6687e1f666e23b69b036`. [Root license: Apache-2.0](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/LICENSE).

**Main companion media.** Its ordinary microphone pipeline opens a 48 kHz context, resamples in an AudioWorklet to the selected target rate, and sends binary PCM frames with a sample-rate header over WebSocket. Construction stays local to a capture attempt; after awaits it checks generation, device selection and route permission before publishing the new pipeline. Losing attempts clean up only their own tracks/context. [app-audio-capture.js:1730–1950](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/static/app/app-audio-capture.js#L1730). Browser output uses scheduled Web Audio playback with separate capture/playback state, not a guarantee of Bluetooth call routing.

**Interruption and stale audio.** `interruptCurrentAssistantSpeech` tracks cancelled speech IDs per socket, advances the input audio epoch, clears queues, and stops scheduled sources. This covers a response's first chunk arriving before playback starts as well as asynchronous decodes already in flight. A server activity cancellation similarly advances the epoch and discards pending blobs/metadata. [app-audio-playback.js:1544–1611](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/static/app/app-audio-playback.js#L1544), [app-websocket.js:1991–2010](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/static/app/app-websocket.js#L1991). Browser playback boundaries are reported separately from provider completion; comments explicitly limit them to this page's observations. [playback.js:578–615](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/static/app/app-audio-playback.js#L578).

**Server cancellation example.** On new typed input the server captures the previous speech ID, tries to interrupt the old producer, clears resampler/TTS queues, notifies user activity, and only then rotates the speech ID. It logs producer interruption failure and proceeds, so this path is not proof of guaranteed cancellation; generation fences remain important. [streaming.py:690–729](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/main_logic/core/streaming.py#L690). This is the typed-input path; do not label it a measured speech-onset timing result.

**Separate RTC path.** A visitor/media transport uses LiveKit with `webAudioMix:false` and owned track publishing/subscription/retry state. It is a separate visit feature, not evidence that the ordinary companion voice pipeline is WebRTC. [livekit-transport.js:110–130](https://github.com/Project-N-E-K-O/N.E.K.O/blob/6cc6cff2caff1dcc6d8b6687e1f666e23b69b036/static/visit/transport/livekit-transport.js#L110).

**Reuse decision.** Strong generation/attempt-ownership and delayed-packet regression scenarios. Do not migrate the entire companion or copy its large custom PCM player to fix our routing. Explicitly distinguish stopping audio from terminating supervised work. Mobile/browser code exists; these inspected files do not demonstrate this Android/car combination working.

## OpenAI Agents JS realtime transport

Pinned `openai/openai-agents-js` at `8aeac0eb255dbdff9adcdc65a0eae638cbcea74f`. [Root license: MIT](https://github.com/openai/openai-agents-js/blob/8aeac0eb255dbdff9adcdc65a0eae638cbcea74f/LICENSE). This is a reference SDK, not the proprietary ChatGPT mobile app's source.

**Media.** Browser transport obtains a microphone stream, attaches its audio track to RTCPeerConnection, and assigns received audio directly to an autoplay HTMLAudioElement's `srcObject`. It uses the data channel for control. Connection attempts are fenced after async device acquisition/signaling, and owned tracks are cleaned up; caller-supplied streams retain caller ownership. [openaiRealtimeWebRtc.ts:500–564](https://github.com/openai/openai-agents-js/blob/8aeac0eb255dbdff9adcdc65a0eae638cbcea74f/packages/agents-realtime/src/openaiRealtimeWebRtc.ts#L500).

**Interruption has two independent actions.** `interrupt()` conditionally sends `response.cancel` and always sends `output_audio_buffer.clear`. Cancelling generation alone is insufficient when output already exists in a playback buffer. [WebRTC transport:803–817](https://github.com/openai/openai-agents-js/blob/8aeac0eb255dbdff9adcdc65a0eae638cbcea74f/packages/agents-realtime/src/openaiRealtimeWebRtc.ts#L803).

**The WebSocket contrast is instructive.** The WS transport emits `audio_interrupted` for the application's player, cancels the response when policy requires it, and sends `conversation.item.truncate` with a bounded audio end time. Its base timing is elapsed wall time from first audio; applications with their own queues must account for actual playout. It avoids discarding transcript estimated already fully played. [openaiRealtimeWebSocket.ts:741–791](https://github.com/openai/openai-agents-js/blob/8aeac0eb255dbdff9adcdc65a0eae638cbcea74f/packages/agents-realtime/src/openaiRealtimeWebSocket.ts#L741). The [official guide](https://openai.github.io/openai-agents-js/guides/voice-agents/build/) distinguishes transport mechanics. This is not an acoustic acknowledgement from car speakers.

**Recovery.** A disconnected connection gets a grace timer; failed/closed connections are closed. This class does not establish seamless cellular handoff or device reconnection: applications still need session/recovery policy. [WebRTC transport:673–716](https://github.com/openai/openai-agents-js/blob/8aeac0eb255dbdff9adcdc65a0eae638cbcea74f/packages/agents-realtime/src/openaiRealtimeWebRtc.ts#L673).

**Reuse decision.** Copy the contract of cancel-generation plus clear-output and heard/unheard history reconciliation, or use the SDK if choosing its provider. Direct adoption changes Jarvis's model/voice path and does not preserve Alfred by merely switching the transport. No Android/car guarantee follows from getUserMedia plus RTC.
